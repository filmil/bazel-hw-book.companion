# Companion examples

This is the example workspace for *Hardware Development with Bazel: Authoring HDL Rules*.
Each target here builds a listing from the book, so you can compare a page and a file line by line.
Where a listing is a fragment, the file adds the least it needs to build, and a comment says what was added.

```sh
bazel test //...                    # every listing that builds, and every test
bazel build //ch01:counter_v        # the Chapter 1 tour
bazel test //ch11:all               # the NVC simulation tests
```

## What you need

You need Bazel (the version in `.bazelversion`) and a C compiler on the host.
Everything else comes from Bazel modules.
`rules_ghdl` builds the GHDL compiler from Ada source through the BCR `ghdl` module.
`rules_nvc` builds the NVC simulator from C source through the `nvc` module of the hdlfactory registry.
The first build compiles both tools and takes a few minutes.
Later builds use the cache.

The book loads the GHDL rules as `@bazel_rules_ghdl`, the ruleset's name before the registry rename (Appendix E).
`MODULE.bazel` imports `rules_ghdl` 1.2.0 under that repository name, so the load statements work as printed.
Version 1.2.0 is the last release with the `ghdl_library` and `ghdl_verilog` API that the book describes.

## Layout

```
ch01/ ... ch22/   one package per chapter that has user-facing listings
design/util/      a VHDL package in its own library
design/counter/   a counter that uses it: two libraries and one deps edge
```

## Claims that CI checks

Some claims in the book are about what fails.
A test cannot check those, so `.forgejo/workflows/ci.yml` runs them as separate steps:

- Chapter 1 says that Bazel derives the compile order from the graph.
  CI deletes the `deps` line in `design/counter/BUILD.bazel` and checks that the build fails with `cannot find resource library "util"`.
- Chapter 3 says that a symbolic macro rejects a misspelled attribute at the call site.
  CI renames `srcs` to `sources` in the symbolic `vhdl_test` call and checks for `no such attribute 'sources' in 'vhdl_test' macro`.
- Chapter 18 prints an aspect command.
  CI runs it as printed and checks the manifest part it writes.

## Coverage by chapter

In the tables, "#3" means the third listing in the chapter, counting code and shell listings alike.
"Internal" means the listing shows the inside of a ruleset: a rule implementation, a provider, a wrapper script, or the ruleset's own `MODULE.bazel`.
That code builds in the ruleset's own repository, and this repository uses it through the module.

The Chapter 21 commands, run against this repository:

```sh
bazel test //ch21:lib_tb_test --zip_undeclared_test_outputs \
    --build_event_json_file=bep.json
jq -r 'select(.id.testResult)
    | [.id.testResult.label, .testResult.status]
    | @tsv' bep.json
jq -r 'select(.id.testResult)
    | .testResult.testActionOutput[]
    | select(.name | endswith("outputs.zip"))
    | .uri' bep.json
```

`vhdl_test` is a macro, so `bazel test` needs the name of the test it stamps, here `lib_tb_test`.
Without `--zip_undeclared_test_outputs`, Bazel 9 lists each output file and writes no `outputs.zip`.

## Where a file differs from the printed listing

Chapter 1's targets live in the `ch01` package here.
So `//:counter_v` in the book is `//ch01:counter_v` in this repository.

The rows above marked "with a fix" record listings that did not build as printed.
Book pull request #62 (https://git.hdlfactory.com/filmil/bazel-hw-book/pulls/62) fixes them in the book.
Once it is merged, those files match the printed listings.
The errors it fixes were these:

- Chapter 1 builds `//core:counter_v` in #2 and `//:counter_v` in #3 and #5.
  Here the target is `//ch01:counter_v`.
- Chapter 3 #3 declares `"entities": attr.string_list()`.
  A symbolic macro's attributes are configurable by default, so the loop receives a `select()` and fails.
  `ch03/vhdl_test_symbolic.bzl` adds `configurable = False`.
- Chapter 9 #4 names its tool `:gen_config_vhd`, which is the genrule itself.
  In the grlib module the tool is `//third_party/grlib/scripts:gen_config_vhd`.
- Chapter 13 #3 offers VHDL-1987 in the flag values.
  NVC 1.22 rejects it with `VHDL standard 1076-1987 is not supported`.
  The book keeps the value, because the listing quotes grlib, and now says that NVC rejects it.
- Chapter 19 #1 loads `@rules_ghdl//:rules.bzl`, while Chapters 1 and 22 load `@bazel_rules_ghdl//:rules.bzl`.
  Both name the same ruleset; this repository uses the second name.
- Chapter 21 #1 needs `rules_vunit` 1.3.0 or later for its `@rules_vunit//:vhdl_*` keys.
  Appendix E names 1.2.2.
- Chapter 21 #3 runs `bazel test` on the macro name and looks for `outputs.zip`.
  The fixes are above.
- Appendix C #2 leaves out `interpreter`, which `rules_kconfig` 0.4.0 requires.

## Versions

The versions in `MODULE.bazel` are ones the two registries in `.bazelrc` serve.
Where Appendix E names a version, this repository uses it, unless a listing needs a later one.
To list what the hdlfactory registry serves for a module:

```sh
curl -s https://raw.githubusercontent.com/filmil/bazel-registry/main/\
modules/rules_ghdl/metadata.json | jq -r '.versions[]'
```
